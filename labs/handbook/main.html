1. What Is Assembly Language?

Imagine you have a robot. The robot only understands very simple commands like "move forward 1 step" or "turn left 90 degrees." You cannot tell the robot "go to the kitchen" because that is too complex. You must break it down into tiny steps.

A CPU (the brain of your computer) is that robot. It only understands machine code: sequences of 0s and 1s like 10110000 01100001. That is hard for humans to read.

Assembly language is a human-readable version of machine code. Instead of 10110000 01100001, you write:

mov al, 61 # put the number 61 into register al

An assembler translates assembly into machine code. A compiler (like gcc) translates C/C++ into assembly, and then the assembler turns that into machine code.

Key Idea

Assembly is the lowest-level human-readable language. Each assembly instruction typically maps to exactly one CPU instruction. C is higher-level: one C line may become 5-10 assembly instructions.

Why Learn Assembly?

  • Understand what the computer actually does - C hides details; assembly shows everything
  • Debug crashes - when your program crashes, the debugger shows assembly
  • Write OS code - operating systems need assembly for traps, context switches, and booting
  • Optimize performance - understand what the compiler does with your C code
  • Reverse engineering - security researchers read assembly to find vulnerabilities

The Compilation Pipeline

# Your C code: int add(int a, int b) { return a + b; } # Step 1: Compiler (gcc) translates C -> Assembly: add: add a0, a0, a1 ret # Step 2: Assembler translates Assembly -> Object file (machine code): # 00000033 (binary: 0000000 01011 01011 000 01010 0110011) # Step 3: Linker combines object files -> Executable: # ./a.out

2. Registers and Memory

Think of registers as the CPU's hands. The CPU can only work with things it holds in its hands. If something is in memory (like a shelf), the CPU must first pick it up (load it into a register), do something with it, then put it back (store it to memory).

Registers are inside the CPU. They are extremely fast (1 cycle) but there are very few of them (16-32 depending on the ISA). Memory (RAM) is outside the CPU, much slower (100+ cycles), but can hold billions of bytes.

Analogy

Registers = your hands (fast, but only 2 of them). Memory = a shelf (slow to reach, but holds everything). Cache = your desk (between hands and shelf, faster than shelf).

Memory Layout

Memory is a giant array of bytes. Each byte has an address (a number). The CPU reads and writes bytes at specific addresses.

# Memory address Content # 0x1000 0x48 ('H') # 0x1001 0x65 ('e') # 0x1002 0x6C ('l') # 0x1003 0x6C ('l') # 0x1004 0x6F ('o') # To read "Hello" from memory into a register: la a0, 0x1000 # a0 = address 0x1000 lb t0, 0(a0) # t0 = 0x48 ('H')

Endianness

When storing a multi-byte value (like a 4-byte integer), which byte goes first?

  • Little-endian (x86, ARM default, RISC-V default): least significant byte first. The number 0x12345678 is stored as 78 56 34 12.
  • Big-endian (MIPS default, network byte order): most significant byte first. The number 0x12345678 is stored as 12 34 56 78.

3. Instruction Formats

Every assembly instruction has the same basic shape:

operation destination, source1, source2 # "Take source1 and source2, do the operation, put the result in destination"

For example:

add a0, a1, a2 # a0 = a1 + a2

But x86-64 is different - it uses two-operand form:

add rax, rbx # rax = rax + rbx (destination is also a source!)

RISC Instruction Types (RISC-V)

RISC-V has exactly 4 core instruction formats. All are 32 bits (4 bytes) wide:

FormatUseFieldsExample
R-typeRegister-registeropcode, rd, funct3, rs1, rs2, funct7add a0, a1, a2
I-typeImmediateopcode, rd, funct3, rs1, imm[11:0]addi a0, a1, 10
S-typeStoreopcode, funct3, rs1, rs2, imm[11:5|4:0]sw a0, 8(sp)
B-typeBranchopcode, funct3, rs1, rs2, imm[12|10:5|4:1|11]beq a0, a1, label
RISC vs CISC

RISC (RISC-V, ARM, MIPS): Fixed 4-byte instructions. Simple, regular, easy to decode. CISC (x86): Variable-length instructions (1-15 bytes). Complex, compact, harder to decode.

4. RISC-V Registers

RISC-V has 32 registers named x0 through x31. But they also have ABI names (nicknames) that describe their job. Think of it like people: everyone has a legal name (x0, x1...) and a nickname (zero, ra, sp...) that tells you their role.

Important Rules
  • x0 is ALWAYS zero. Writing to it does nothing. Reading it always gives 0.
  • sp must be 16-byte aligned at function entry.
  • a0-a7 hold the first 8 arguments to a function.
  • a0 holds the return value.
  • ra holds the return address (where to go after the function returns).

Caller-Saved vs Callee-Saved

This is one of the most important concepts in assembly. It is a contract between the caller and the callee (the function being called):

  • Caller-saved (t0-t6, a0-a7): The caller must save these if it needs them after a call. The callee is free to trash them.
  • Callee-saved (ra, sp, s0-s11): The callee must save these before using them and restore them before returning. The caller can rely on them being unchanged.
Memory Aid

a = arguments (a0-a7). s = saved (s0-s11). t = temporary (t0-t6). ra = return address. sp = stack pointer.

7. RISC-V Calling Convention

Imagine you and your friend are working together. You have some tools on your desk. When you ask your friend to do a task, you both need rules:

  • "I will put the inputs in these specific spots (a0-a7)"
  • "I will look for the result in this spot (a0)"
  • "If I need my desk tools after you finish, I will save them first (caller-saved)"
  • "If you use my permanent tools, you must put them back (callee-saved)"

The Rules

  1. Arguments: Pass in a0-a7 (first 8). Extra args go on the stack.
  2. Return value: In a0 (and a1 for 16-byte returns).
  3. Stack alignment: sp must be 16-byte aligned at function entry.
  4. Return address: ra (x1) holds the return address.
  5. Frame pointer: s0/fp (x8) optionally points to the top of the frame.

Standard Prologue and Epilogue

# Function prologue - set up the stack frame addi sp, sp, -32 # allocate 32 bytes sd ra, 24(sp) # save return address sd s0, 16(sp) # save frame pointer sd s1, 8(sp) # save s1 addi s0, sp, 16 # set frame pointer # ... function body ... # Function epilogue - tear down the stack frame ld ra, 24(sp) # restore return address ld s0, 16(sp) # restore frame pointer ld s1, 8(sp) # restore s1 addi sp, sp, 32 # deallocate stack ret # return to caller

8. x86-64 Registers

x86-64 has 16 registers. They evolved from the old 8086 CPU (1978) which had just 4 registers (AX, BX, CX, DX). Over time, more were added. The names are historical: AX = Accumulator, BX = Base, CX = Count, DX = Data.

x86-64 has NO zero register!

Unlike RISC-V (x0) and ARM64 (xzr), x86-64 has no hardwired zero register. To zero a register, use xor eax, eax (shorter than mov eax, 0).

9. x86-64 Instructions

Arithmetic (Two-Operand Form!)

Key Difference from RISC-V

x86-64 uses two-operand form: op dest, src. The destination is ALSO a source. add rax, rbx means rax = rax + rbx.

InstructionMeaning
mov dest, srcdest = src
add dest, srcdest = dest + src
sub dest, srcdest = dest - src
imul dest, srcdest = dest * src
and dest, srcdest = dest & src
or dest, srcdest = dest | src
xor dest, srcdest = dest ^ src
shl dest, countdest = dest << count
shr dest, countdest = dest >> count (logical)
sar dest, countdest = dest >> count (arithmetic)
inc destdest = dest + 1
dec destdest = dest - 1
neg destdest = -dest
lea dest, [addr]dest = address (no memory access!)

Memory Addressing

x86-64's most powerful feature: any instruction can access memory. No need for separate load/store instructions.

# Format: [base + index*scale + displacement] # scale can be 1, 2, 4, or 8 mov rax, [rbx] # rax = *rbx (load) mov [rbx], rax # *rbx = rax (store) mov eax, [rbx + 8] # eax = *(rbx + 8) mov eax, [rbx + rcx*4] # eax = rbx[rcx] (array access) lea rax, [rdi + rsi] # rax = rdi + rsi (no memory access!)

MIPS Branch Delay Slot

MIPS has a branch delay slot: the instruction after a branch/jump is always executed before the branch takes effect. This is a pipeline optimization. Modern MIPS and RISC-V do NOT have delay slots (RISC-V never did).

17. Syscalls and Traps

Your program runs in user mode (unprivileged). It cannot directly access hardware, network, or files. When it needs to do something privileged (like writing to screen), it must ask the kernel to do it. This request is called a system call (or syscall). The mechanism to switch from user mode to kernel mode is called a trap.

Syscall Numbers (Linux)

OperationRISC-Vx86-64ARM64

Making a Syscall in Assembly

# --- RISC-V: write(1, msg, 14) then exit(0) --- li a7, 64 # syscall number: write = 64 li a0, 1 # fd = stdout la a1, msg # buffer li a2, 14 # length ecall # trap into kernel li a7, 93 # syscall number: exit = 93 li a0, 0 # status = 0 ecall # --- x86-64: write(1, msg, 14) then exit(0) --- mov rax, 1 # syscall number: write = 1 mov rdi, 1 # fd = stdout mov rsi, msg # buffer mov rdx, 14 # length syscall # trap into kernel mov rax, 60 # syscall number: exit = 60 xor rdi, rdi # status = 0 syscall
