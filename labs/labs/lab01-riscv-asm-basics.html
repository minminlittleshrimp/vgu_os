Lab 01: RISC-V Assembly Basics

Write and run your first RISC-V assembly programs. Learn registers, arithmetic, memory, control flow, and function calls.

Objectives

  • Write and execute RISC-V assembly programs using the simulator
  • Use the 32 general-purpose registers (x0-x31) and the RISC-V calling convention
  • Perform load/store operations with ld/sd and arithmetic with add, sub, mul
  • Implement loops and branches using bge, beq, j
  • Write and call functions using call/ret and the ra register
  • Read and understand compiler-generated assembly from C source code

Prerequisites

  • Basic familiarity with the C programming language
  • Understanding of binary and hexadecimal number representation
  • Complete the Assembly Handbook chapters 1-7 (Foundations + RISC-V)
  • Open the RISC-V Simulator in a browser tab
Quick Reference
RISC-V has 32 registers named x0 through x31. Register x0 is always zero. The ABI names are: ra (x1), sp (x2), a0-a7 (x10-x17) for arguments, t0-t6 for temporaries, and s0-s11 for saved registers.
Hands-On Exercise 1: Hello RISC-V - Compile C, Read Assembly

Start by writing a simple C program, compiling it to RISC-V assembly, and reading the output. This builds the mental model of what the compiler does.

Open the simulator

Navigate to ../simulator/main.html in your browser. You will see a code editor on the left and an output panel on the right.

Enter the following C code
int main() { int a = 10; int b = 20; int c = a + b; return c; }
Compile and observe the assembly

Click the Compile button. The simulator will display the generated RISC-V assembly. Look for the main label.

Identify key instructions

Find and note down each of these in the output:

  • The li (load immediate) instruction that sets a0 to 10
  • The add instruction that computes a0 + a1 or similar
  • The ret instruction at the end of main
Run the program

Click Run. The return value (30) should appear in the output panel as the exit code in a0.

What to Notice
The compiler may optimize away variables a and b and just do li a0, 30. Try compiling with -O0 (no optimization) to see the full variable storage on the stack.
Hands-On Exercise 2: Register Basics - li, mv, add

Write raw RISC-V assembly that adds 10 and 20 using registers. This teaches you the fundamental register-move and arithmetic instructions.

Switch to assembly mode

In the simulator, select Assembly mode from the language dropdown.

Enter this assembly code
main: li a0, 10 # Load immediate 10 into a0 li a1, 20 # Load immediate 20 into a1 add a0, a0, a1 # a0 = a0 + a1 = 30 ret # Return (a0 holds the result)
Run and verify

Click Run. The exit code should be 30 (0x1E).

Experiment with mv

Modify the program to use mv to copy a value between registers:

main: li t0, 42 mv a0, t0 # a0 = t0 (copy) ret

Run it - the exit code should be 42.

Try subtraction and multiplication

Replace add with sub (subtract) and then mul (multiply). Verify the results:

  • sub a0, a1, a0 -> 20 - 10 = 10
  • mul a0, a0, a1 -> 10 x 20 = 200
Hands-On Exercise 3: Load/Store - sd and ld

Learn how to store data to memory (the stack) and load it back. This is essential for understanding how local variables work.

Understand the stack pointer

The stack pointer sp (x2) points to the top of the stack. We allocate stack space by subtracting from sp.

Enter this store-and-load program
main: addi sp, sp, -16 # Allocate 16 bytes on stack li t0, 42 # Load value 42 into t0 sd t0, 0(sp) # Store t0 (8 bytes) at sp+0 ld a0, 0(sp) # Load it back into a0 addi sp, sp, 16 # Restore stack pointer ret
Run and verify

The exit code should be 42. The value was stored to memory and loaded back.

Store multiple values

Modify the program to store two values at different offsets:

li t0, 100 li t1, 200 sd t0, 0(sp) # Store 100 at offset 0 sd t1, 8(sp) # Store 200 at offset 8 ld a0, 8(sp) # Load 200 into a0

Run it - the exit code should be 200.

Important
sd stores a 64-bit (doubleword) value. For 32-bit, use sw (store word). Always restore sp before returning, or you will corrupt the caller's stack frame.
Hands-On Exercise 4: Loop - Sum 1 to 10

Write a loop that sums the numbers 1 through 10 using branch instructions. This teaches control flow in assembly.

Understand the loop structure

A loop needs: a counter register, an accumulator register, a comparison, and a conditional branch. We will use:

  • t0 = counter (starts at 1)
  • t1 = limit (10)
  • t2 = accumulator (starts at 0)
Enter the loop program
main: li t0, 1 # counter = 1 li t1, 10 # limit = 10 li t2, 0 # sum = 0 loop: add t2, t2, t0 # sum += counter addi t0, t0, 1 # counter++ ble t0, t1, loop # if counter <= 10, loop mv a0, t2 # a0 = sum (return value) ret
Run and verify

The exit code should be 55 (1+2+3+...+10 = 55).

Trace the execution

Use the Step button in the simulator to execute one instruction at a time. Watch how t0 increments and t2 accumulates. Count how many times the loop label is reached.

Modify the limit

Change the limit from 10 to 100. Run again - the result should be 5050.

Branch Instructions
  • beq - branch if equal
  • bne - branch if not equal
  • blt - branch if less than (signed)
  • bge - branch if greater or equal (signed)
  • ble - branch if less or equal (signed)
  • bgt - branch if greater than (signed)
  • j - unconditional jump
Hands-On Exercise 5: Function Call - call and ret

Write a function add_two that takes two arguments and returns their sum. Call it from main.

Understand the calling convention

Arguments are passed in a0-a7. Return value goes in a0. The call pseudo-instruction saves the return address in ra and jumps. ret jumps back to ra.

Enter the program
main: li a0, 15 # First argument li a1, 27 # Second argument call add_two # Call function (ra = return addr) ret # Return from main add_two: add a0, a0, a1 # a0 = a0 + a1 ret # Return to caller (ra)
Run and verify

The exit code should be 42 (15 + 27).

Add a third function

Add a triple_add function that takes three arguments and calls add_two internally:

triple_add: # a0, a1, a2 are the three arguments # Save a2 because add_two will clobber a0 mv t0, a2 # Save a2 in t0 call add_two # a0 = a0 + a1 add a0, a0, t0 # a0 = a0 + a2 ret

Call it with li a0, 10; li a1, 20; li a2, 30; call triple_add. Result should be 60.

Caller-Saved Registers
Registers a0-a7 and t0-t6 are caller-saved. If you need their values after a call, you must save them yourself (on the stack or in a callee-saved register). Lab 02 covers this in depth.
Hands-On Exercise 6: Read Compiler Output

Compile a C function and identify each instruction the compiler generates. This bridges the gap between C and assembly.

Enter this C code in the simulator
int compute(int x, int y) { int result = x * 2 + y; if (result > 100) { return result; } else { return 0; } }
Compile with -O0

Set optimization to -O0 and compile. Read through the generated assembly.

Identify these instructions

Fill in this table as you find each pattern:

C CodeRISC-V Instruction(s)Notes
x * 2?May use add or slli
+ y?Look for add
result > 100?Look for li + ble or bgt
return result?Look for mv a0, ...
return 0?Look for li a0, 0 or mv a0, x0
Compile with -O2 and compare

Switch to -O2 and recompile. Notice how the compiler:

  • Eliminates the stack frame (no addi sp, sp, ...)
  • Keeps everything in registers
  • May use slli (shift left) instead of add for x * 2
  • May rearrange branches for efficiency
Write down the instruction count

Count the number of instructions in the compute function at -O0 vs -O2. Record the difference.

Key Insight
The compiler is very good at eliminating unnecessary memory operations. At -O0, every variable is stored on the stack. At -O2, the compiler keeps values in registers and removes dead code. This is why reading optimized assembly can look very different from the C source.
