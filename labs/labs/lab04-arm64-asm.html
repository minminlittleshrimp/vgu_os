Lab 04: ARM64 (AArch64) Assembly Programming

Learn ARM64 assembly: 31 registers, load/store pair instructions, conditional select, and the AAPCS64 calling convention.

Objectives

  • Write and run ARM64 (AArch64) assembly programs
  • Use the 31 general-purpose registers (x0-x30) and the special roles of xzr, sp, lr (x30), fp (x29)
  • Master load/store pair instructions: stp / ldp (two registers at once)
  • Use the conditional select instruction csel for branchless code
  • Understand the AAPCS64 calling convention (x0-x7 for args, bl/ret)
  • Understand ARM privilege levels (EL0-EL3) and exception handling basics
  • Compare ARM64 with RISC-V

Prerequisites

  • Complete Lab 01 and Lab 02
  • Read Handbook Chapters 11-13 (ARM64 registers, instructions, calling convention)
  • Open the Simulator (supports ARM64 mode)

Hands-On Exercise 1: Hello ARM64 - Compile C, Read Assembly

Compile a simple C function to ARM64 and read the generated assembly.

Open the simulator

Navigate to ../simulator/main.html and select ARM64 / AArch64 as the target.

Enter this C code
int add(int a, int b) { return a + b; }
Compile and read the output

You should see something like:

add: add w0, w0, w1 # w0 = w0 + w1 (32-bit) ret # return (result in w0)
Note the ARM64 conventions
  • Arguments in x0-x7 (64-bit) or w0-w7 (32-bit)
  • Return value in x0 / w0
  • w prefix = 32-bit, x prefix = 64-bit
  • Link register is x30 (also called lr)
  • Stack pointer is sp (separate from x0-x30)
Hands-On Exercise 2: Register Basics - mov, add, sub

Write ARM64 assembly using mov, add, and sub. ARM64 uses 3-operand form like RISC-V.

Switch to assembly mode

Select Assembly mode and ARM64 architecture in the simulator.

Enter this program
.globl main main: mov x0, #10 # x0 = 10 mov x1, #20 # x1 = 20 add x0, x0, x1 # x0 = x0 + x1 = 30 ret # return x0
Run and verify

The exit code should be 30.

Try subtraction and multiplication
# Subtraction sub x0, x1, x0 # x0 = x1 - x0 = 10 # Multiplication mul x0, x0, x1 # x0 = x0 * x1

Verify: sub gives 10, mul gives 200.

Compare with RISC-V

ARM64's 3-operand form (add x0, x0, x1) is identical to RISC-V's (add a0, a0, a1). The main difference is register naming: ARM64 uses x0-x30, RISC-V uses x0-x31 / a0-a7.

Immediate Format
ARM64 uses # prefix for immediates: mov x0, #10. RISC-V does not: li a0, 10. Also, ARM64 mov only works with 16-bit immediates. For larger values, use movz/movk or the ldr pseudo-instruction.
Hands-On Exercise 3: Load/Store Pair - stp and ldp

ARM64 has unique stp (store pair) and ldp (load pair) instructions that transfer two registers at once. This is very useful for function prologues.

Understand stp/ldp

stp x0, x1, [sp] stores both x0 and x1 to consecutive memory locations. ldp x0, x1, [sp] loads them back. This is twice as efficient as separate str/ldr instructions.

Enter the prologue/epilogue program
.globl main main: # Prologue: save fp and lr (link register) in one instruction stp x29, x30, [sp, #-16]! # push fp, lr; sp -= 16 mov x29, sp # set frame pointer # Body: store and load values mov x0, #42 str x0, [sp, #16] # store at sp+16 ldr x0, [sp, #16] # load it back # Epilogue: restore fp and lr in one instruction ldp x29, x30, [sp], #16 # pop fp, lr; sp += 16 ret
Run and verify

The exit code should be 42.

Understand pre-index and post-index
  • [sp, #-16]! - pre-index: subtract 16 from sp first, then access
  • [sp], #16 - post-index: access sp first, then add 16
  • [sp, #16] - offset: access sp+16, don't modify sp
Compare with RISC-V

In RISC-V, saving ra and s0 requires three instructions:

# RISC-V equivalent addi sp, sp, -16 sd ra, 8(sp) sd s0, 0(sp)

ARM64 does it in one: stp x29, x30, [sp, #-16]!

Why stp/ldp Matters
stp/ldp are heavily used in ARM64 function prologues and epilogues. Saving fp (x29) and lr (x30) together is the most common pattern. This is why ARM64 code often looks cleaner than RISC-V for function entry/exit.
Hands-On Exercise 4: Conditional Select - csel (Branchless Max)

ARM64 has a unique csel (conditional select) instruction that chooses between two values based on condition flags - without branching. This enables branchless code.

Understand csel

csel x0, x1, x2, cond - if condition is true, x0 = x1; otherwise x0 = x2. The condition comes from a prior cmp instruction.

Write a branchless max function
.globl main main: mov x0, #15 # first value mov x1, #42 # second value call max # x0 = max(15, 42) ret max: # x0 = first arg, x1 = second arg cmp x0, x1 # compare x0 and x1 csel x0, x0, x1, gt # if x0 > x1, x0 = x0; else x0 = x1 ret
Run and verify

The exit code should be 42 (max of 15 and 42).

Test with reversed values

Swap the values: mov x0, #99; mov x1, #42. The result should be 99.

Compare with branch-based max

The same logic with a branch would be:

max_branch: cmp x0, x1 b.gt done # if x0 > x1, skip mov x0, x1 # else x0 = x1 done: ret

The csel version has no branch, which avoids branch misprediction penalties on modern CPUs.

Branchless Programming
csel is one of ARM64's superpowers. Branchless code avoids pipeline flushes caused by mispredicted branches. RISC-V and x86-64 need cmov (x86) or branch-based equivalents. ARM64's csel is more flexible because it can select from any two registers.
Hands-On Exercise 5: Function Call - bl/ret, x0-x7 args

Write a function that takes two arguments and returns their sum, using the AAPCS64 calling convention.

Learn the AAPCS64 convention
RegisterRole
x0-x7Arguments 1-8
x0Return value
x29 (fp)Frame pointer (callee-saved)
x30 (lr)Link register (return address)
spStack pointer (must be 16-byte aligned)
x19-x28Callee-saved registers
x9-x15Caller-saved temporaries
Enter the program
.globl main main: mov x0, #15 # 1st arg mov x1, #27 # 2nd arg bl add_two # branch with link (saves lr) ret add_two: add x0, x0, x1 # x0 = x0 + x1 ret # return to lr
Run and verify

The exit code should be 42 (15 + 27).

Add a stack frame

For functions that call other functions:

add_two: stp x29, x30, [sp, #-16]! # save fp, lr mov x29, sp add x0, x0, x1 ldp x29, x30, [sp], #16 # restore fp, lr ret
bl vs call
ARM64 uses bl (branch with link) instead of call. bl saves the return address in x30 (lr). ret branches to x30. This is equivalent to RISC-V's call (saves in ra) and ret (branches to ra).

ARM Privilege Levels
ARM64 has four Exception Levels (EL0-EL3): EL0 = user mode, EL1 = kernel/OS, EL2 = hypervisor, EL3 = secure monitor. Transitions between levels use eret (exception return). This is analogous to RISC-V's privilege modes (U, S, M) and sret/mret.
