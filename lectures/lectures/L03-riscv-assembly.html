SECTION 1

Assembly Basics

Why we still write assembly . C-to-asm mapping . pseudo-instructions

Why Assembly?

"Assembly is like reading the chef's recipe instead of the menu. You see exactly what goes into each dish."

When you need assembly

Most OS code is written in C. But some pieces must be in assembly because they touch hardware directly or have no C equivalent:

  • Boot code - runs before C runtime is ready
  • Trap handlers - save/restore registers at the ISA level
  • Context switches - swap register sets atomically
  • Inline asm - atomic operations, CSR access from C

In xv6, assembly lives in .S files

These are the files you will read and modify throughout the course:

FilePurpose
entry.SM-mode boot: set up PMP, switch to S-mode
trampoline.SUser trap entry (uservec) and exit (userret)
swtch.SContext switch: save/restore callee-saved regs
kernelvec.SKernel trap handler

Convention

.S (capital S) files are processed by the C preprocessor - you can use #include and macros. .s (lowercase) files are not.

From C to Assembly

C function

int add(int a, int b)
{
    return a + b;
}

Equivalent RISC-V assembly

add:
    add a0, a0, a1   # a0 = a0 + a1
    ret              # return to caller

Register mapping

The compiler follows the calling convention to map C constructs to registers:

C conceptRegisterABI name
First argument (a)x10a0
Second argument (b)x11a1
Return valuex10a0
Return addressx1ra

Key insight

The same register a0 carries the first argument in and the return value out. The function body overwrites it with the result before returning.

Key Pseudo-Instructions

Pseudo-instructions are convenience aliases. The assembler expands them into one or more real machine instructions.

Pseudo-instructionExpands toMeaning
li rd, immlui + addiLoad immediate (any 64-bit constant)
mv rd, rsaddi rd, rs, 0Move (copy register)
la rd, symbolauipc + addiLoad address of a symbol
j labeljal x0, offsetUnconditional jump (discard return addr)
retjalr x0, 0(ra)Return to caller (jump to ra)
call symboljal ra, offsetCall function (save return addr in ra)
nopaddi x0, x0, 0No operation
neg rd, rssub rd, x0, rsNegate (two's complement)
not rd, rsxori rd, rs, -1Bitwise NOT

Why pseudo-instructions matter

You will see ret, call, mv, and la everywhere in xv6 assembly. Knowing what they expand to helps you understand the actual machine code.

SECTION 2

Calling Convention

The contract between caller and callee . stack frames . prologue/epilogue

RISC-V Calling Convention

The contract

The calling convention defines who is responsible for which registers across a function call. Both caller and callee must agree, or data gets corrupted.

RoleRegistersABI names
Argumentsx10-x17a0-a7
Return valuex10a0
Return addressx1ra
Stack pointerx2sp
Frame pointerx8s0 / fp

Caller-saved (volatile)

The callee may freely clobber these. If the caller needs them after a call, it must save them first.

  • t0-t6 - temporaries
  • a0-a7 - arguments / return

Callee-saved (preserved)

The callee must save and restore these if it uses them. The caller can rely on them surviving a call.

  • s0-s11 - saved registers
  • sp - stack pointer
  • ra - return address (if callee calls others)

Alignment rule

sp must be 16-byte aligned at every call boundary.

Stack Frame Layout

Key points

The stack grows down (toward lower addresses). fp (s0) marks the top of the current frame; sp marks the bottom. The frame size = fp - sp.

Function Prologue and Epilogue

Standard function template

func:
    # ---- prologue ----
    addi sp, sp, -16    # allocate frame
    sd   ra, 8(sp)      # save return address
    sd   s0, 0(sp)     # save callee-saved reg
    mv   s0, a0         # use s0 for local work

    # ---- function body ----
    # ... do work using s0 ...

    mv   a0, s0         # set return value

    # ---- epilogue ----
    ld   s0, 0(sp)      # restore callee-saved
    ld   ra, 8(sp)      # restore return addr
    addi sp, sp, 16     # deallocate frame
    ret                 # return to caller

Prologue (setup)

1. Allocate frame: addi sp, sp, -N - move sp down by N bytes.

2. Save ra and any callee-saved registers you plan to use.

3. Move arguments into s registers if you need them preserved across calls.

Epilogue (teardown)

1. Set return value in a0.

2. Restore callee-saved registers and ra from the stack.

3. Deallocate frame: addi sp, sp, N - move sp back up.

4. ret - jump to ra.

Mirror symmetry

The epilogue is the exact mirror of the prologue. Every sd has a matching ld; the addi signs are reversed.

SECTION 3

Memory Access Patterns

Load/store instructions . struct field access . stack push/pop

Load and Store Instructions

RISC-V is a load/store architecture: arithmetic operates only on registers. Memory access happens through explicit load/store instructions.

Load instructions (memory -> register)

InstructionSizeExtension
lw rd, off(rs)4 bytes (word)sign-extend
ld rd, off(rs)8 bytes (double)sign-extend
lb rd, off(rs)1 bytesign-extend
lbu rd, off(rs)1 bytezero-extend
lwu rd, off(rs)4 byteszero-extend

Store instructions (register -> memory)

InstructionSize
sw rs, off(rs1)4 bytes (word)
sd rs, off(rs1)8 bytes (double)
sb rs, off(rs1)1 byte
sh rs, off(rs1)2 bytes (half)

Addressing form

Every load/store uses base_reg + offset:

ld t0, 8(sp) -> loads 8 bytes from address sp + 8 into t0.

Working with Structs

Accessing struct fields

A struct's fields live at fixed offsets from the struct base pointer. You access them with ld/lw using the offset.

// a0 = pointer to trapframe
ld t0, 24(a0)
# loads 8 bytes from a0+24
# = trapframe->epc

Why this works

The compiler knows the layout. 24 is the byte offset of the epc field within struct trapframe. In hand-written assembly, you compute these offsets manually.

Stack Operations: Push and Pop

Push (save a register onto the stack)

# push one 8-byte register
addi sp, sp, -8     # make room
sd   ra, 0(sp)      # store register

# push two registers (keep 16-byte alignment)
addi sp, sp, -16
sd   ra, 8(sp)
sd   s0, 0(sp)

Pop (restore a register from the stack)

# pop one register
ld   ra, 0(sp)      # load register
addi sp, sp, 8      # reclaim space

# pop two registers
ld   ra, 8(sp)
ld   s0, 0(sp)
addi sp, sp, 16

The stack grows DOWN

To push, you first decrease sp, then store. To pop, you first load, then increase sp.

16-byte alignment

sp must always be a multiple of 16 at a call instruction. If you push an odd number of 8-byte registers, add padding.

push = addi sp,sp,-N ; sd reg,0(sp)
pop = ld reg,0(sp) ; addi sp,sp,N

Mental model

Think of the stack as a stack of plates. You add to the bottom (lower address) and remove from the bottom. The top of the stack is always at sp.

SECTION 4

Control Flow in Assembly

Branches . jumps . if-else . loops

Branches and Jumps

Conditional branches

All take rs1, rs2, offset. They compare two registers and branch if the condition is true.

InstructionCondition
beq rs1, rs2, labelif rs1 == rs2
bne rs1, rs2, labelif rs1 != rs2
blt rs1, rs2, labelif rs1 < rs2 (signed)
bge rs1, rs2, labelif rs1 >= rs2 (signed)
bltu rs1, rs2, labelif rs1 < rs2 (unsigned)
bgeu rs1, rs2, labelif rs1 >= rs2 (unsigned)

Pseudo-branches

beqz rs, label = beq rs, x0, label; bnez, bgt, ble, etc. are also available.

Unconditional jumps

InstructionEffect
jal rd, offsetrd = PC+4; PC += offset
jalr rd, rs1, immrd = PC+4; PC = rs1 + imm

Pseudo-jump forms

PseudoExpands to
j labeljal x0, offset
retjalr x0, 0(ra)
call symboljal ra, offset
jr rsjalr x0, 0(rs)

jal vs jalr

jal uses a PC-relative offset (good for nearby code). jalr uses a register + immediate (good for indirect calls, returns, function pointers).

If-Else in Assembly

C code

if (a0 > 0)
    a0 = 1;
else
    a0 = 0;

Equivalent assembly

    bgt  a0, x0, true   # if a0 > 0, goto true
    li   a0, 0           # else: a0 = 0
    j    end            # skip the true branch
true:
    li   a0, 1           # a0 = 1
end:
    ret

Pattern: inverted condition

Assembly branches on the condition to skip the body. The C if (cond) body becomes b!cond, skip; body; skip:.

Step by step

  1. bgt a0, x0, true - if a0 > 0, jump to true label.
  2. If not taken, fall through: li a0, 0 (else branch).
  3. j end - skip over the true branch.
  4. true: label - li a0, 1.
  5. end: - both paths converge here, then ret.

Common mistake

Forgetting the j end after the else-body causes fall-through into the true branch - both branches execute!

Loops in Assembly

C code

int sum = 0;
for (int i = 0; i < n; i++)
    sum += a[i];

Equivalent assembly

# a0 = array ptr, a1 = n
# s0 = sum, s1 = i, s2 = ptr

    li   s0, 0           # sum = 0
    li   s1, 0           # i = 0
    mv   s2, a0          # ptr = a0
loop:
    bge  s1, a1, done    # if i >= n, exit
    lw   t0, 0(s2)       # t0 = *ptr
    add  s0, s0, t0      # sum += t0
    addi s2, s2, 4       # ptr++ (4 bytes)
    addi s1, s1, 1       # i++
    j    loop            # repeat
done:
    mv   a0, s0          # return sum
    ret

Loop structure

Every loop has three parts:

  1. Init - set up counters, pointers, accumulators.
  2. Condition - branch out when done (bge here).
  3. Body + increment - do work, advance, jump back.

Pointer arithmetic

addi s2, s2, 4 advances by 4 bytes (one int). For long or pointers (8 bytes), use addi s2, s2, 8.

Register choice

s0, s1, s2 are callee-saved - they survive across calls inside the loop. If the loop body calls a function, use s registers for loop variables.

SECTION 5

Inline Assembly in C

GCC asm syntax . CSR access . atomic operations

GCC Inline Assembly

Syntax

asm volatile("instruction"
  : output_operands
  : input_operands
  : clobber_list);

Operands

  • output - "=r" (var) means "write result to var via any register."
  • input - "r" (var) means "read var from any register."
  • clobber - "memory" tells the compiler the asm may read/write memory.

volatile

Prevents the compiler from optimizing away or reordering the asm - critical for hardware register access.

Example from xv6 - riscv.h

// Read the satp CSR (page table base)
static inline uint64
r_satp()
{
  uint64 x;
  asm volatile("csrr %0, satp"
               : "=r" (x));
  return x;
}

What happens here

  • %0 is a placeholder for the first operand (x).
  • "=r" (x) tells GCC: "put the output in x, using any general register."
  • The assembler emits csrr <reg>, satp.
  • volatile ensures the read is not optimized away.

Reading and Writing CSRs

CSR = Control and Status Register. These are special registers for privilege, traps, and configuration - accessible only in S-mode or M-mode.

InstructionAction
csrr rd, csrRead CSR -> rd
csrw csr, rsWrite rs -> CSR
csrrw rd, csr, rsRead CSR -> rd, then write rs -> CSR
csrrs rd, csr, rsRead CSR, set bits from rs
csrrc rd, csr, rsRead CSR, clear bits from rs

Pseudo forms

csrw csr, imm = csrrw x0, csr, imm (write immediate, discard old value).

xv6 CSR accessor functions

These inline-asm wrappers live in riscv.h and are used throughout the kernel:

FunctionCSRPurpose
r_sstatus()sstatusSupervisor status
w_stvec()stvecTrap vector address
r_sepc()sepcException PC
r_scause()scauseTrap cause
r_satp()satpPage table base
r_tp()tpThread pointer (hartid)

Why inline asm?

There is no C operator for "read CSR." Inline asm is the only way to access these from C without dropping to a full assembly file.

Atomic Operations

Atomic memory operation

amoswap.w.aq rd, rs, (rs1)
# atomically:
# rd = M[rs1] (load old)
# M[rs1] = rs (store new)
# all in one indivisible step

Breakdown

  • amo - atomic memory operation
  • swap - swap register with memory
  • .w - word size (4 bytes)
  • .aq - acquire fence (no later loads/stores move before this)

xv6 spinlock acquire

From spinlock.c - the heart of mutual exclusion:

void
acquire(struct spinlock *lk)
{
    push_off();  // disable interrupts
    while (atomic_swap(&lk->locked, 1) != 0)
        ;  // spin until we get the lock
    lk->cpu = mycpu();
}

static inline int
atomic_swap(int *addr, int val)
{
    int old;
    asm volatile("amoswap.w.aq %0, %1, (%2)"
                 : "=r" (old)
                 : "r" (val), "r" (addr)
                 : "memory");
    return old;
}

Why atomic?

Without atomicity, two CPUs could both read locked == 0 and both write 1 - a race condition. amoswap makes the load+store indivisible.

SECTION 6

xv6 Assembly Files

entry.S . trampoline.S . swtch.S . kernelvec.S

xv6 Assembly Files Overview

FileModePurposeKey symbols
entry.S M-mode First code to run after QEMU boot. Sets up PMP, stack, switches to S-mode. _entry, start
trampoline.S S <-> U User trap entry (uservec) and exit (userret). Saves/restores user registers via trapframe. uservec, userret
swtch.S S-mode Context switch between kernel threads. Saves/restores callee-saved registers. swtch
kernelvec.S S-mode Kernel trap handler for interrupts/exceptions while in the kernel. kernelvec, kerneltrap

When each runs

  • entry.S - once, at boot
  • trampoline.S - every user trap (syscall, timer, fault)
  • swtch.S - every context switch (scheduler)
  • kernelvec.S - device interrupts while in kernel

Reading order

Start with entry.S (simplest), then swtch.S (short), then trampoline.S (most complex). kernelvec.S is similar to trampoline.S but simpler.

entry.S Walkthrough

Code (simplified)

.section .text.init
.globl _entry
_entry:
    # 1. Read hart ID into tp
    csrr  t0, mhartid

    # 2. Compute stack for this hart
    la    sp, stack0
    li    t1, 4096       # PGSIZE
    mul   t1, t1, t0
    add   sp, sp, t1     # sp = stack0 + hartid*PGSIZE

    # 3. Jump to C code (start.c)
    call  start

spin:
    wfi
    j     spin

Step-by-step

  1. csrr t0, mhartid - read the hardware thread ID. Each CPU core (hart) gets a unique number.
  2. la sp, stack0 - load the base address of the pre-allocated stack array.
  3. mul + add - offset the stack by hartid x PGSIZE so each hart has its own 4 KB stack.
  4. call start - jump to the C function start() in start.c, which configures PMP, delegation, and does mret into S-mode.
  5. wfi + j spin - if start ever returns (it shouldn't), spin forever waiting for interrupts.

Key details

  • This runs in M-mode (machine mode) - the most privileged level.
  • tp (thread pointer) is set later in start() and used by mycpu().
  • The stack is per-hart - multiple CPUs boot simultaneously and must not share a stack.

swtch.S Walkthrough

Code (simplified)

.globl swtch
swtch:
    # a0 = old context ptr
    # a1 = new context ptr

    # --- save old context ---
    sd   ra,  0(a0)
    sd   sp,  8(a0)
    sd   s0, 16(a0)
    sd   s1, 24(a0)
    # ... s2-s11 ...
    sd   s11, 96(a0)

    # --- load new context ---
    ld   ra,  0(a1)
    ld   sp,  8(a1)
    ld   s0, 16(a1)
    ld   s1, 24(a1)
    # ... s2-s11 ...
    ld   s11, 96(a1)

    ret   # jump to new ra

What swtch does

swtch(old, new) saves the callee-saved registers of the currently running thread into old, then loads the callee-saved registers from new and returns.

Why only callee-saved?

Caller-saved registers (t0-t6, a0-a7) are already on the stack or dead at the call site. Only ra, sp, and s0-s11 need saving - the compiler guarantees they are live across calls.

The magic of ret

After loading ra from the new context, ret jumps to that ra - not the original caller. This is how execution "switches" to the new thread. The new thread's ra was saved when it was last switched out.

Context = struct context

The "context" is just a struct holding ra, sp, and s0-s11 - 14 registers x 8 bytes = 112 bytes. Each process has one in its proc struct.

Key Takeaways

Assembly is the chef's recipe

You see exactly what the CPU executes - no abstraction layer. Needed for boot, traps, context switches, and atomic ops.

Calling convention is the contract

Caller-saved vs callee-saved. Arguments in a0-a7, return in a0, sp 16-byte aligned. Break it and data corrupts.

Stack frames are the workspace

Prologue allocates + saves; epilogue restores + deallocates. The stack grows down. fp marks the top, sp the bottom.

Inline asm bridges C and hardware

CSR access, atomic operations, and special instructions - all done via asm volatile with output/input/clobber operands.

What to do next

Open entry.S, swtch.S, and trampoline.S in xv6. Trace through them line by line. You now have every concept needed to understand them fully.
