SECTION 1

Interrupts Overview

What is an interrupt . polling vs interrupt . RISC-V interrupt types

What is an Interrupt?

"An interrupt is like a doorbell. You're working on something, the doorbell rings, you put down your work (save state), answer the door (handle interrupt), then pick up where you left off (restore state)."

Definition

A hardware signal that suspends current execution. The CPU saves state, runs a handler, then resumes.

Three types in xv6

  • External - device I/O (UART, virtio disk)
  • Timer - periodic clock tick
  • Software - inter-processor (not used in xv6)

RISC-V: scause high bit

When bit 63 of scause is set, the trap is an interrupt (not an exception). The remaining bits identify which one.

scause = 0x8000000000000009
// bit 63 = 1 -> interrupt
// bits 0-62 = 9 -> external (PLIC)

Where it starts

All interrupts enter kernelvec (kernel mode) or uservec (user mode), then dispatch to trap.c functions.

Interrupt vs Polling

Polling

CPU repeatedly checks device status in a loop. Simple to implement, but wastes CPU cycles spinning while waiting.

// Polling: spin until device is ready
while ((ReadReg(LSR) & LSR_TX_IDLE) == 0)
    ;  // burn CPU cycles

When polling is fine

Early boot before interrupts are configured, or panic output where you cannot afford to sleep.

Interrupt

Device notifies CPU only when ready. Efficient - CPU does other work meanwhile. But more complex: need PLIC, handler, locking.

// Interrupt: sleep until woken
sleep_prepare(&tx_chan);
if (ReadReg(LSR) & LSR_TX_IDLE) {
    WriteReg(THR, c);  // send
} else {
    sleep();  // yield, no spinning
}

xv6 uses both

Interrupts for UART RX and timer. uartputc_sync() uses polling for panic/early boot. uartwrite() uses interrupt-driven sleep.

RISC-V Interrupt Types

From trap.c devintr(): checks scause high bit, then dispatches.

scause valueTypeHandlerSource
0x8000000000000009 External (PLIC) uartintr() or virtio_disk_intr() UART, virtio disk
0x8000000000000005 Timer clockintr() Supervisor timer

devintr() dispatch

int
devintr()
{
  uint64 scause = r_scause();
  if ((scause & 0x8000000000000000L) &&
       scause == 0x8000000000000009L) {
    int irq = plic_claim();
    if (irq == UART0_IRQ)
      uartintr();
    else if (irq == VIRTIO0_IRQ)
      virtio_disk_intr();
    plic_complete(irq);
    return 1;  // external
  } else if (scause == 0x8000000000000005L) {
    clockintr();
    return 2;  // timer
  }
  return 0;
}

Return value matters

devintr() returns 1 for external, 2 for timer, 0 for unknown. The caller (usertrap / kerneltrap) uses this to decide whether to call yield().

Timer -> yield()

If which_dev == 2 (timer), usertrap() calls yield() to give another process a turn. This is preemptive scheduling.

SECTION 2

PLIC

Platform-Level Interrupt Controller . routing external interrupts

What is PLIC?

The Platform-Level Interrupt Controller routes external interrupts from devices to the CPU. Each device has an IRQ number.

IRQ numbers (memlayout.h)

DeviceIRQ
UART010
VIRTIO01

PLIC base address

0x0C000000 - memory-mapped registers for enable, priority, threshold, claim, and complete.

Key registers

  • Priority - per-IRQ priority level
  • Enable - bit per IRQ, per hart
  • Threshold - minimum priority to accept
  • Claim - read to get pending IRQ
  • Complete - write to signal done

PLIC Interrupt Flow

From trap.c

plic_claim() reads the claim register and returns the IRQ number. plic_complete(irq) writes the complete register so PLIC can deliver the next interrupt.

Must complete

If you forget plic_complete(), the PLIC will never deliver another interrupt for that device. The claim/complete handshake is mandatory.

PLIC Initialization

plicinit() in trap.c - called during boot in main().

Code

void
plicinit(void)
{
  // Set priority for UART and VIRTIO
  *(uint32*)(PLIC + UART0_IRQ*4) = 1;
  *(uint32*)(PLIC + VIRTIO0_IRQ*4) = 1;

  // Enable UART interrupts for hart 0
  *(uint32*)(PLIC_MENABLE) = (1 << UART0_IRQ);
  *(uint32*)(PLIC_SENABLE) = (1 << UART0_IRQ);

  // Enable VIRTIO interrupts
  *(uint32*)(PLIC_SENABLE + 4) =
      (1 << (VIRTIO0_IRQ % 32));

  // Set threshold for hart 0
  *(uint32*)(PLIC_STHRESHOLD) = 0;
}

What it does

  1. Priority - set to 1 for both UART0 and VIRTIO0 (higher = more urgent)
  2. Enable - set the bit for each IRQ in the enable register
  3. Threshold - set to 0 (accept all priorities >= 0)

M-mode vs S-mode

xv6 enables interrupts in both M-mode (PLIC_MENABLE) and S-mode (PLIC_SENABLE). The S-mode enable is what matters once the kernel drops to supervisor mode.

When it runs

Called early in main(), before consoleinit() and before scheduler(). Interrupts are not yet enabled globally (r_sstatus() SIE bit) until later.

UART Driver

16550a UART . uartinit . uartwrite . uartintr

16550a UART

From uart.c: UART0 at 0x10000000. Memory-mapped registers accessed via ReadReg() / WriteReg().

RegisterOffsetPurpose
RHR0Receive Holding (read byte)
THR0Transmit Holding (write byte)
IER1Interrupt Enable
FCR2FIFO Control
ISR2Interrupt Status
LCR3Line Control
LSR5Line Status

Key status bits

BitMeaning
LSR_RX_READY (1<<0)Byte available to read
LSR_TX_IDLE (1<<5)Transmit buffer empty

Key interrupt bits

BitMeaning
IER_RX_ENABLE (1<<0)Interrupt on receive
IER_TX_ENABLE (1<<1)Interrupt on transmit ready

RHR and THR share offset 0

Reading offset 0 gives received data (RHR). Writing offset 0 sends data (THR). The direction of the operation selects which register.

uartinit()

Called from consoleinit() during boot. Configures baud rate, line format, FIFOs, and interrupts.

Code

void
uartinit(void)
{
  // Disable interrupts
  WriteReg(IER, 0x00);

  // Baud rate 38.4K: enable DLAB
  WriteReg(LCR, LCR_BAUD_LATCH);

  // Divisor = 3 (38400 baud)
  WriteReg(0, 0x03);
  WriteReg(1, 0x00);

  // 8-bit, no parity
  WriteReg(LCR, LCR_EIGHT_BITS);

  // Enable FIFOs, clear them
  WriteReg(FCR,
    FCR_FIFO_ENABLE | FCR_FIFO_CLEAR);

  // Enable RX and TX interrupts
  WriteReg(IER,
    IER_RX_ENABLE | IER_TX_ENABLE);

  // Init sleep lock and channel
  initsleeplock(&tx_lock, "uart");
}

Step by step

  1. Disable interrupts - safe to reconfigure while IER = 0
  2. Baud rate - set DLAB bit in LCR, write divisor (3 = 38400 baud)
  3. Line control - 8 data bits, no parity, 1 stop bit (LCR_EIGHT_BITS)
  4. FIFOs - enable and clear both RX and TX FIFOs
  5. Enable interrupts - RX (byte received) and TX (transmit ready)
  6. Lock - initialize tx_lock sleep lock for uartwrite()

Why a sleep lock?

uartwrite() may need to wait for the TX buffer to drain. A sleep lock lets the process sleep (yield CPU) instead of spinning, while still preventing concurrent access.

uartwrite() - Interrupt-Driven Write

Blocking write using a sleep lock. Sends n bytes from buf, sleeping when the TX buffer is full.

Code

void
uartwrite(char buf[], int n)
{
  acquiresleep(&tx_lock);
  int i = 0;
  while (i < n) {
    sleep_prepare(&tx_chan);
    if (ReadReg(LSR) & LSR_TX_IDLE) {
      WriteReg(THR, buf[i]);
      i += 1;
    } else {
      sleep();  // yield until TX ready
    }
  }
  releasesleep(&tx_lock);
}

How it works

  1. Acquire the sleep lock - only one writer at a time
  2. Prepare to sleep on tx_chan - register as a waiter
  3. If TX is idle, write one byte to THR and advance
  4. If TX is busy, sleep - yield CPU until uartintr() wakes us
  5. Release the lock when done

Why not spin?

Spinning wastes CPU while the UART slowly transmits each byte. Sleeping lets other processes run. The TX interrupt (uartintr()) calls wakeup(&tx_chan) when the buffer drains.

Sleep lock, not spinlock

A spinlock would disable interrupts - but uartwrite needs interrupts to fire so uartintr can wake it. Sleep locks do not disable interrupts.

uartputc_sync() - Polling Write

Non-interrupt spinning write. Used for panic and early boot when interrupts may not work.

Code

void
uartputc_sync(int c)
{
  if (panicking == 0)
    push_off();  // disable interrupts

  // Spin until TX buffer is empty
  while ((ReadReg(LSR) & LSR_TX_IDLE) == 0)
    ;

  // Send the byte
  WriteReg(THR, c);

  if (panicking == 0)
    pop_off();  // restore interrupt state
}

When to use this

  • Panic - interrupts may be broken; must not sleep
  • Early boot - before uartinit() sets up interrupts
  • Console during init - before sleep locks are ready

push_off / pop_off

These manage a nested interrupt-disable counter. If we are already in a context with interrupts off (e.g., holding a spinlock), push_off remembers that and pop_off restores the original state.

Why not sleep?

During panic, the scheduler may be corrupted. Calling sleep() could deadlock forever. Polling guarantees the byte goes out, even if nothing else works.

uartintr() - Interrupt Handler

Called from devintr() when PLIC delivers a UART interrupt. Handles both RX and TX.

Code

void
uartintr(void)
{
  // Read ISR to acknowledge
  ReadReg(ISR);

  // If TX is idle, wake the sender
  if (ReadReg(LSR) & LSR_TX_IDLE)
    wakeup(&tx_chan);

  // Drain all received bytes
  while (1) {
    int c = uartgetc();
    if (c == -1)
      break;
    consoleintr(c);  // pass to console
  }
}

Two jobs

  1. TX wakeup - if the transmit buffer is now idle, wake any process sleeping in uartwrite() on tx_chan
  2. RX drain - read all available bytes from RHR and pass each to consoleintr(c)

Acknowledge first

Reading ISR (Interrupt Status Register) acknowledges the interrupt at the UART level. Without this, the UART keeps asserting the interrupt line.

Drain the FIFO

The while(1) loop reads until uartgetc() returns -1 (no more data). This handles multiple bytes queued in the RX FIFO from a single interrupt.

SECTION 4

Console Driver

Console layer . input flow . consoleread . consolewrite

Console Layer

From console.c: the console sits between user-space read()/write() syscalls and the UART hardware.

Console buffer

struct cons {
  spinlock lock;
  char buf[128];  // input buffer
  uint r;          // read index
  uint w;          // write index
  uint e;          // edit index
} cons;

consoleinit()

void
consoleinit(void)
{
  initlock(&cons.lock, "cons");
  uartinit();
  devsw[CONSOLE].read  = consoleread;
  devsw[CONSOLE].write = consolewrite;
}

Device number

CONSOLE = 1 - the major device number. When a process opens /dev/console (or fd 0/1/2), the kernel uses devsw[CONSOLE] to dispatch reads and writes.

Two directions

  • Input - UART RX -> uartintr() -> consoleintr(c) -> cons.buf -> consoleread() -> user space
  • Output - user space -> consolewrite() -> uartwrite() -> UART TX

Locking

cons.lock is a spinlock protecting the circular buffer. It is held briefly during consoleintr and consoleread buffer operations.

Console Input Flow

consoleintr() handles special keys

  • C('P') = Ctrl-P -> procdump()
  • C('U') = Ctrl-U -> kill line
  • C('H') / \x7f -> backspace
  • Default -> echo + store in cons.buf

Line discipline

The console does line editing: it buffers input until newline or EOF, then wakes consoleread(). This is a simple in-kernel line discipline.

consoleread()

Called when a user process calls read() on the console fd. Blocks until a full line is available.

Code (simplified)

int
consoleread(int user_dst, uint64 dst, int n)
{
  uint target = n;
  acquire(&cons.lock);
  while (cons.r == cons.w) {
    if (myproc()->killed) {
      release(&cons.lock);
      return -1;
    }
    sleep(&cons.r, &cons.lock);
  }
  // Copy from cons.buf to user space
  for (int i = 0; i < n && cons.r != cons.w; i++) {
    char c = cons.buf[cons.r++ % 128];
    if (copyout(...) == -1) break;
    if (c == '\n') { i++; break; }
  }
  release(&cons.lock);
  return i;
}

How it works

  1. Acquire cons.lock
  2. If buffer is empty (r == w), sleep on &cons.r
  3. When woken (by consoleintr after newline), copy bytes from cons.buf to user space via copyout()
  4. Stop at newline or when n bytes copied
  5. Release lock and return byte count

Sleep with lock

sleep(&cons.r, &cons.lock) atomically releases the lock while sleeping and reacquires it before returning. This prevents consoleintr from writing while we read.

Killed check

If the process is killed while waiting, consoleread returns -1 immediately. Without this check, a killed process would hang forever in sleep().

consolewrite()

Called when a user process calls write() on the console fd. Copies data from user space and sends to UART.

Code (simplified)

int
consolewrite(int user_src, uint64 src, int n)
{
  int i;
  for (i = 0; i < n; i++) {
    char c;
    // Copy byte from user space
    if (either_copyin(
        &c, user_src, src+i, 1) == -1)
      break;
    uartputc(c);
  }
  return i;
}

How it works

  1. Loop over each byte requested
  2. Copy one byte from user (or kernel) space via either_copyin()
  3. Send it to UART via uartputc() (which calls uartwrite internally)
  4. Return number of bytes written

No line buffering on output

Unlike input (which buffers until newline), output goes straight to UART. There is no output line discipline - bytes are sent as soon as possible.

either_copyin

Handles both user-space and kernel-space source addresses. This lets consolewrite work whether called from a syscall (user buffer) or from kernel code (e.g., printf).

SECTION 5

Timer Interrupts

clockintr . preemptive scheduling . yield

Timer Interrupt

From trap.c clockintr(): fires periodically, drives the tick counter and wakes sleepers.

Code

void
clockintr()
{
  // Increment tick counter
  ticks++;

  // Wake up all sleep()ers
  wakeup(&ticks);

  // Schedule next timer interrupt
  w_stimecmp(r_time() + 1000000);
}

What it does

  1. Increment ticks - global tick counter
  2. Wakeup - wake any process sleeping on &ticks (e.g., sleep() syscall)
  3. Reschedule - set next timer via w_stimecmp(r_time() + 1000000)

scause = 0x8000000000000005

This is the supervisor timer interrupt. devintr() returns 2 for timer, which tells usertrap() to call yield().

stimecmp

w_stimecmp() writes the stimecmp CSR. When r_time() reaches this value, the next timer interrupt fires. The 1000000 is the tick interval (in QEMU's clock units).

Preemptive Scheduling

The timer interrupt is what makes xv6 preemptive. Without it, a process could run forever.

The chain

Timer -> yield() -> sched() -> swtch() -> scheduler() -> next process. This happens every tick, giving each process a time slice.

Without timer interrupts

A CPU-bound process that never calls yield() voluntarily would monopolize the CPU. No other process would ever run. The timer interrupt forces preemption.

Cooperative vs preemptive

If scheduling only happened when processes voluntarily yield, it would be cooperative. The timer makes xv6 preemptive - the OS takes control back regardless of what the process is doing.

which_dev == 2

In usertrap(), after handling the trap, if which_dev == 2 (timer), the kernel calls yield(). Other interrupts (which_dev == 1) do not trigger a yield.

SECTION 6

Device Switch

devsw table . device files . everything is a file

devsw - Device Switch Table

From file.h: a table of function pointers that dispatches read/write to the right driver.

Definition

struct devsw {
  int (*read)(int, uint64, int);
  int (*write)(int, uint64, int);
};

struct devsw devsw[NDEV];

// In consoleinit():
devsw[CONSOLE].read  = consoleread;
devsw[CONSOLE].write = consolewrite;

How it is used

In fileread() and filewrite(), when the file type is FD_DEVICE:

// fileread()
if (f->type == FD_DEVICE) {
  return devsw[f->major].read(
      f->minor, addr, n);
}

// filewrite()
if (f->type == FD_DEVICE) {
  return devsw[f->major].write(
      f->minor, addr, n);
}

Major and minor

Major selects the driver (index into devsw[]). Minor selects a sub-device (passed as the first argument to the driver's read/write). For the console, major = CONSOLE (1), minor = 0.

Device Files

The Unix "everything is a file" model: devices are accessed through the same open/read/write interface as regular files.

mknod()

Creates a device file in the filesystem:

mknod("/dev/console",
      1, 0);
//        ^  ^
//   major  minor

This creates a file whose inode records major=1 (CONSOLE), minor=0.

open()

When open() sees a device file, it returns a file descriptor with type = FD_DEVICE and stores the major/minor numbers.

read() / write() dispatch

  1. read(fd, buf, n) -> fileread()
  2. fileread() checks f->type == FD_DEVICE
  3. Calls devsw[f->major].read(f->minor, ...)
  4. For console: consoleread()

Why this matters

User programs do not need to know about UART, PLIC, or console buffers. They just call read() and write(). The kernel dispatches to the right driver transparently.

Extensibility

To add a new device, implement read/write functions and register them in devsw[]. No changes to fileread/filewrite needed.

Key Takeaways

Interrupts = doorbell

Hardware signals that suspend execution. Three types: external (PLIC), timer, software. scause bit 63 set for interrupts.

PLIC routes interrupts

Devices -> PLIC -> CPU. Claim register gets IRQ, complete register clears it. plic_claim() / plic_complete() in trap.c.

UART driver = two modes

uartwrite() sleeps on TX interrupt. uartputc_sync() polls for panic/boot. uartintr() handles RX + TX wakeup.

Timer = preemption

clockintr() increments ticks, wakes sleepers, reschedules. yield() -> sched() -> swtch() gives each process a time slice.

Everything is a file

devsw[] dispatches read/write to drivers by major number. mknod() creates device files. User code sees only read()/write().

Console = line discipline

consoleintr() buffers input until newline. consoleread() blocks until a line is ready. consolewrite() sends straight to UART.
