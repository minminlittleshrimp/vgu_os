Pattern

Every shared structure embeds its own lock. struct proc has a spinlock; struct inode has a sleeplock (because I/O can sleep). This is the foundation of xv6's concurrency discipline.

SECTION 2

Boot Sequence

From QEMU power-on to the scheduler - every step traced

Boot Path - QEMU to scheduler()

entry.s - M-mode entry

Runs before page tables exist

entry.S is the very first code to execute. There are no page tables yet - all addresses are physical. The kernel is loaded at 0x80000000 by QEMU.

What it does

  • Sets tp = mhartid (hardware thread ID)
  • Sets sp = stack0 + hartid x PGSIZE (per-hart stack)
  • Sets up PMP (physical memory protection) - allow all access
  • Calls start() in start.c

Why per-hart stacks

Each hardware thread (hart) gets its own stack, offset by hartid x PGSIZE from stack0. This prevents stack collisions when multiple harts boot simultaneously.

kernel/entry.S (simplified)
.section .text
.globl entry
entry:
    # set up per-hart stack
    csrr  t0, mhartid        # read hart ID
    la    sp, stack0
    li    t1, 4096           # PGSIZE
    mul   t0, t0, t1
    add   sp, sp, t0         # sp = stack0 + hartid*PGSIZE

    # call start.c (still in M-mode)
    call  start

    # should never get here
spin:
    wfi
    j     spin

Key point

At this stage the MMU is off. la sp, stack0 resolves to a physical address. Paging is not enabled until kvminithart() runs later in main().

start.c - M-mode -> S-mode

Purpose

start() performs the one-time M-mode setup that must happen before dropping to S-mode, then executes mret to enter main() in S-mode.

Delegation

Sets medeleg and mideleg to forward exceptions and interrupts to S-mode. Without this, all traps stay in M-mode and the S-mode trap handler never runs.

Timer

Configures the supervisor timer (sbicall to set timer clock) so timervec can generate periodic interrupts for preemption.

The mret trick

Sets sstatus.SPP = 1 (so mret returns to S-mode), sets sepc = main (so mret jumps to main()), then executes mret.

kernel/start.c (simplified)
void
start()
{
    // delegate exceptions & interrupts to S-mode
    unsigned long x = (1 << 5) | (1 << 7) | (1 << 11);
    asm volatile("csrw medeleg, %0" : : "r"(x));
    asm volatile("csrw mideleg, %0" : : "r"(x));

    // configure PMP - allow all access in S-mode
    asm volatile("csrw pmpaddr0, %0" : : "r"(0x3fffffffffffff));
    asm volatile("csrw pmpcfg0, %0" : : "r"(0xf));

    // set S-mode return point
    asm volatile("csrw mepc, %0" : : "r"(main));

    // set SPP=1 so mret returns to S-mode
    unsigned long y;
    asm volatile("csrr %0, mstatus" : "=r"(y));
    y |= (1 << 11);   // MSTATUS_SPP
    asm volatile("csrw mstatus, %0" : : "r"(y));

    // drop to S-mode, jump to main()
    asm volatile("mret");
}

main.c - Initialization sequence

Each init function sets up one subsystem

main() calls a series of *init() functions in a strict order. Each one initializes exactly one kernel subsystem. The order matters - later inits depend on earlier ones.

CallSets up
consoleinit()Console + UART driver
uartinit()16550A UART registers
kvminit()Kernel page table (empty)
kvmmake()Install kernel mappings
procinit()Process table + per-proc locks
trapinit()Trap vector (stvec)
trapinithart()Per-hart trap setup
binit()Buffer cache
iinit()Inode cache
fileinit()File table
virtio_disk_init()VirtIO disk driver
userinit()First user process (initcode)
scheduler()Start scheduling - never returns
kernel/main.c (simplified)
void
main()
{
    if (cpuid() == 0) {
        consoleinit();
        uartinit();
        printfinit();
        kvminit();          // create kernel page table
        kvmmake();           // map kernel segments
        procinit();          // process table
        trapinit();          // trap vectors
        trapinithart();      // per-hart trap setup
        binit();             // buffer cache
        iinit();             // inode cache
        fileinit();          // file table
        virtio_disk_init();  // disk driver
        userinit();          // first user process
        __sync_synchronize();
        started = 1;
    } else {
        // other harts wait, then set up traps
        while (started == 0)
            ;
        __sync_synchronize();
        trapinithart();
    }
    scheduler();  // <-- never returns
}

Multi-hart boot

Only hart 0 runs the full init sequence. Other harts spin on started until initialization is complete, then call trapinithart() and enter scheduler().

SECTION 3

Adding a System Call

The 5-step process - from user stub to kernel dispatch

The 5-Step Process

To add a new system call (e.g., sys_getppid), you touch five files. No more, no less.

Steps 1-2: User Side

Step 1 - user/user.h

Add the function prototype so user programs can call getppid() as if it were a normal C function.

user/user.h
// system calls
int fork(void);
int exit(int) __attribute__((noreturn));
int wait(int*);
int kill(int);
int getpid();
int getppid();          // <-- ADD THIS
int sleep(int);
int exec(char*, char**);
// ...

Why a header prototype is needed

The C compiler needs to know the return type and argument count. Without the prototype, the compiler generates incorrect calling code.

Step 2 - user/usys.pl

usys.pl is a Perl script that generates usys.S - the actual assembly stubs. Each entry() call produces a small assembly function.

user/usys.pl
sub entry {
    my $name = shift;
    print ".global $name\n";
    print "${name}:\n";
    print " li a7, SYS_${name}\n";
    print " ecall\n";
    print " ret\n";
}

entry("fork");
entry("exit");
entry("getppid");       # <-- ADD THIS
# ...

Generated assembly

Each stub loads the syscall number into a7, executes ecall (trap to kernel), then returns. The kernel reads a7 from the trapframe to dispatch.

Steps 3-4: Kernel Dispatch

Step 3 - kernel/syscall.h

Assign a unique number to the new syscall. The number must not collide with existing entries.

kernel/syscall.h
// System call numbers
#define SYS_fork    1
#define SYS_exit    2
#define SYS_wait    3
#define SYS_kill    6
#define SYS_getpid  11
#define SYS_getppid 23    // <-- ADD THIS
// ...

Number must be unique

The number is the key into the dispatch array. A duplicate silently routes calls to the wrong handler.

Step 4 - kernel/syscall.c

Add an entry to the syscalls[] array, mapping the number to the implementation function. Also add a function prototype.

kernel/syscall.c
static uint64 (*syscalls[])(void) = {
[SYS_fork]    sys_fork,
[SYS_exit]    sys_exit,
[SYS_wait]    sys_wait,
[SYS_getpid]  sys_getpid,
[SYS_getppid] sys_getppid,   // <-- ADD THIS
// ...
};

void
syscall(void)
{
    int num;
    struct proc *p = myproc();

    num = p->trapframe->a7;       // read syscall number
    if (num > 0 && num < NELEM(syscalls)
        && syscalls[num]) {
        p->trapframe->a0 = syscalls[num]();  // call, store return in a0
    } else {
        p->trapframe->a0 = -1;    // unknown syscall
    }
}

Step 5: Implementation

Step 5 - kernel/sys_proc.c

Implement the actual logic. The function takes no arguments in C - arguments are fetched from the trapframe using argraw(), argint(), or argaddr().

kernel/sys_proc.c
uint64
sys_getppid(void)
{
    struct proc *p = myproc();
    return p->parent->pid;
}

Why no C arguments

The syscall stub in usys.S puts arguments in registers (a0-a5) before ecall. The kernel reads them from p->trapframe->a0 etc. via the arg* helpers - not from the C calling convention.

Argument helpers

FunctionReturnsUse for
argraw(n)uint64Raw register value from trapframe
argint(n, &ip)int via pointerInteger arguments
argaddr(n, &ip)uint64 via pointerPointer/address arguments
argstr(n, buf, max)int (length)String arguments (via copyinstr)

Example: syscall with arguments

uint64
sys_kill(void)
{
    int pid;
    if (argint(0, &pid) < 0)
        return -1;
    return kill(pid);
}

argint(0, ...) reads a0 from the trapframe. Argument index 0 = first argument, 1 = second, etc.

SECTION 4

Kernel Coding Conventions

Locking, memory allocation, and the user/kernel boundary

Locking Discipline

Rule 1: Every shared structure has a lock

struct proc has lock, struct spinlock guards cpus[], struct inode has a sleeplock. If two cores can touch it, it needs a lock.

Rule 2: Acquire before access, release after

Pattern: acquire(&lock) -> read/write shared data -> release(&lock). Never access shared data outside a critical section.

Rule 3: push_off() / pop_off()

push_off() disables interrupts and increments a per-CPU counter. pop_off() decrements and re-enables when the counter hits zero. This prevents deadlocks when a lock is acquired inside an interrupt handler.

Rule 4: Never sleep holding a spinlock

If you need to sleep (wait for I/O), use a sleeplock instead. A spinlock held across sleep() would deadlock the scheduler.

How spinlock works - spinlock.c

acquire() uses amoswap (atomic swap) to test-and-set the locked field. If already locked, it spins (busy-waits) until the holder releases.

kernel/spinlock.c (simplified)
void
acquire(struct spinlock *lk)
{
    push_off();          // disable interrupts
    if (holding(lk))
        panic("acquire");

    // atomic test-and-set via amoswap
    while (__sync_lock_test_and_set(
               &lk->locked, 1) != 0)
        ;

    __sync_synchronize();
    lk->cpu = mycpu();
}

void
release(struct spinlock *lk)
{
    lk->cpu = 0;
    __sync_synchronize();
    __sync_lock_release(&lk->locked);
    pop_off();           // re-enable interrupts
}

Two lock types

Spinlock: CPU spins, interrupts off, for short critical sections. Sleeplock: process sleeps, interrupts on, for long waits (disk I/O).

Memory Allocation - kalloc.c

The allocator

kalloc() allocates 4 KB pages from a free list. kfree() returns pages to the free list. The free list is a linked list of struct run, one per free page.

Debugging aid: junk fill

When a page is allocated, kalloc() fills it with 0x05 (or similar). When freed, kfree() fills it with 0x01 (or junk). This catches dangling references - if you see 0x05 bytes, you're reading uninitialized memory; if you see 0x01, you're reading freed memory.

Locking

The free list is protected by kmem.lock - a single spinlock for the entire allocator. kalloc() and kfree() both acquire it.

kernel/kalloc.c (simplified)
struct run {
    struct run *next;
};

struct {
    struct spinlock lock;
    struct run *freelist;
} kmem;

void *
kalloc(void)
{
    struct run *r;

    acquire(&kmem.lock);
    r = kmem.freelist;
    if (r)
        kmem.freelist = r->next;
    release(&kmem.lock);

    if (r)
        memset((char*)r, 5, PGSIZE); // fill with junk
    return r;
}

void
kfree(void *pa)
{
    struct run *r = (struct run*)pa;

    // fill with junk to catch stale refs
    memset((char*)pa, 1, PGSIZE);

    acquire(&kmem.lock);
    r->next = kmem.freelist;
    kmem.freelist = r;
    release(&kmem.lock);
}

User / Kernel Copy - vm.c

Never dereference user pointers directly

A user pointer (e.g., char* passed to write()) lives in the user's virtual address space. The kernel runs with a different page table. Direct dereference either faults or reads the wrong memory.

Always use copyin / copyout

These functions walk the user's page table and safely copy bytes between user virtual addresses and kernel buffers. They handle page boundaries and invalid mappings gracefully.

FunctionDirectionPurpose
copyin(pagetable, dst, srcva, len)user -> kernelCopy len bytes from user va to kernel buf
copyout(pagetable, dstva, src, len)kernel -> userCopy len bytes from kernel buf to user va
copyinstr(pagetable, dst, srcva, max)user -> kernelCopy a null-terminated string from user space

How it works

copyin() uses walkaddr() to translate each user virtual address to a physical address through the process's page table, then memmove()s the data. It handles the case where the range spans multiple pages.

kernel/vm.c (simplified)
int
copyin(pagetable_t pagetable, char *dst,
       uint64 srcva, uint64 len)
{
    uint64 n, va0, pa0;

    while (len > 0) {
        va0 = PGROUNDDOWN(srcva);
        pa0 = walkaddr(pagetable, va0);
        if (pa0 == 0)
            return -1;

        n = PGSIZE - (srcva - va0);
        if (n > len)
            n = len;

        memmove(dst, (void *)(pa0 + (srcva - va0)), n);

        len -= n;
        dst += n;
        srcva = va0 + PGSIZE;
    }
    return 0;
}

Why this matters

Without copyin/copyout, a malicious or buggy user program could pass a kernel address and read/write kernel memory. This is the security boundary between user and kernel space.

SECTION 5

Console and Output

How printf works in the kernel, and how input flows from UART to user

printk - How printf works in the kernel

The call chain

printf() -> consolewrite() (if from user) or direct uartputc() (if from kernel). The console layer buffers output; the UART driver transmits bytes.

Two output paths

  • Kernel printf: calls uartputc_sync() - spins until the UART transmit buffer is empty. Used during boot and panic, when interrupts may be off.
  • Console write (from user write()): consolewrite() copies bytes from user space via copyin(), then calls uartwrite() which buffers and uses interrupt-driven TX.

UART hardware

16550A UART at 0x10000000. Registers: THR (transmit), RHR (receive), LSR (line status - TX ready, RX ready). Interrupt-driven for normal I/O; polled (spin) for panic.

Console Input

Interrupt-driven RX

When the UART receives a byte, it raises an interrupt. uartintr() reads RHR and calls consoleintr() for each byte.

Line editing in consoleintr()

KeyAction
Ctrl-Pprocdump() - print process table
Ctrl-UKill line - erase entire input buffer
BackspaceErase last character
Ctrl-DEOF - end of input (if buffer empty)
EnterWake consoleread(), deliver line
Printable charAppend to cons.buf, echo

Input buffer

Input is buffered in cons.buf[INPUT_BUF] (128 bytes). consoleread() blocks on sleep() until a full line (Enter) is available, then copies to user space via copyout().

Summary - Key Takeaways

1. Kernel = init functions + scheduler

main() calls a sequence of *init() functions, each setting up one subsystem, then calls scheduler() which never returns. The boot path is: entry.S (M-mode) -> start.c (M->S) -> main() (S-mode).

2. Syscalls are 5 steps

user.h prototype -> usys.pl stub -> syscall.h number -> syscall.c dispatch -> sys_*.c implementation. The ecall instruction bridges user and kernel.

3. Always use locks

Every shared structure has a lock. acquire/release for spinlocks, sleeplock for long waits. push_off/pop_off manage interrupt state. Never sleep holding a spinlock.

4. Never dereference user pointers

Always use copyin() / copyout() / copyinstr() to move data across the user/kernel boundary. Direct dereference is a security hole and a crash waiting to happen.

5. kalloc fills with junk

kalloc() fills pages with 0x05; kfree() fills with 0x01. This catches dangling references and use-after-free bugs during development.

6. Console is layered

UART (hardware) -> uartintr/uartputc (driver) -> consoleintr/consolewrite (line discipline) -> consoleread (user-facing). Interrupt-driven for normal I/O, polled for panic.
